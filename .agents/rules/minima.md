# Minima Rules

- Minima RPC commands should be sent as a single URL path command, not as query parameters. Build the command string first, for example `megammrsync action:resync host:megammr.minima.global:9001`, then percent-encode it into the path: `http://minima:9005/megammrsync%20action%3Aresync%20host%3Amegammr.minima.global%3A9001`.
- Do not expose a generic Minima command proxy. Add narrow, allowlisted backend actions for each supported command.
- The RPC console (`backend/src/features/minima/minima-console.catalog.ts` / `minima-console.service.ts`) is a deliberate, scoped exception to the rule above, not a generic proxy: it only ever runs a command that is both present in the static, closed-world catalog and enabled in the admin whitelist (`GET`/`POST /api/minima/console/whitelist`), so no request body can execute anything outside that catalog. `vault`, `sendfrom`, `signfrom`, `createfrom`, `postfrom`, `createtokenfrom`, `decryptbackup`, `keys`, and `quit` are hard-excluded — not offered as checkboxes at all — because they can expose or accept raw wallet private keys/seed phrases, or (for `quit`) halt the node with no UI recovery path. Every other catalog command defaults to enabled if read-only and disabled if it mutates anything (funds, chain, config, network, wallet). Whitelist edits require re-entering the admin PIN/password (`POST /api/minima/console/whitelist`, same re-auth pattern as `changePassword`). Where a whitelisted command already has a dedicated narrow action (`megammrsync` → `resyncMegammr()`, `peers action:addpeers` → `addMinimaPeers()`, `backup` → `createBackup()`, `restoresync` → `restoreBackup()`), the console dispatches to that same function instead of re-implementing the RPC call, so operation-tracking, audit logging, and error normalization stay a single source of truth.
- Node backup/restore (`backend/src/features/minima/minima-backup.service.ts`, `POST/GET/DELETE /api/minima/backups*`) is a first-class, UI-driven feature, not just console passthrough: `backup` writes a `.bak` file (seed phrase, private keys, coin proofs, transaction history — a superset of the seed-phrase-only wallet import in `wallet.service.ts`) into the shared `${MINIMA_DATA_DIR}/backups` host directory, and restore always uses `restoresync` (restore + Megammr re-sync in one step) against the configured Megammr host. Plain `restore` (no resync) and `reset` stay console-only, raw passthrough. Downloading or restoring a backup requires re-entering the admin PIN/password, same re-auth pattern as the console whitelist, because a backup file may contain unencrypted key material.
- `${MINIMA_DATA_DIR}/backups` is mounted into **both** containers: into `backend` read-write at the fixed path `/minima-backups` (the only backend↔minima shared host directory — never the rest of `MINIMA_DATA_DIR`), and into `minima` at `/home/minima/backups`. The second mount is required, not cosmetic: verified live against the pinned image, Minima resolves the `backup`/`restoresync` `file:` argument relative to its home dir (`/home/minima`), not `/home/minima/data` — without this mount, `backup file:backups/<name>.bak` silently lands in the container's ephemeral layer and is lost on restart, invisible to `backend`.
